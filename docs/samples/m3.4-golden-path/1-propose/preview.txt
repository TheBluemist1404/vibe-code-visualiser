  why:      Rejected students only get the reason inside the message text. Enrollment already stores the machine-readable reason (enrollment.types.ts Enrollment.reason; enrollment.service.ts enroll()), but Notification (notification.types.ts) has no such field, so the web page cannot show it. Add a nullable reason attribute to the Notification data, set only on enrollment-rejected notifications, and describe the web page showing it. Left unchanged on purpose: Enrollment data, seat-limit rule, module dependencies (mod-notifications stays dependency-free, so the reason is typed string there like Enrollment.reason, not a reference), no events/contracts, confirmed enrollments and their notifications, capabilities, and the message texts.

Confirmed notifications have no reason.

  ✓? A COURSE_FULL rejection produces a notification with reason COURSE_FULL, and the message text is unchanged
  ✓? An ALREADY_ENROLLED rejection produces a notification with reason ALREADY_ENROLLED
  ✓? A confirmed enrollment's notification has no reason field and is otherwise unchanged
  ✓? GET /api/notifications returns the reason for rejected notifications
  ✓? The web page shows the reason next to a rejected notification and nothing extra for confirmed ones
  ✓? The notifications module does not import from the enrollment module (no new module dependency)

  test: NotificationsService: keeps each recipient's notifications separate, in order
